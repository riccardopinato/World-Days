# World Days — Retention / Native Layer

Verified implementation date: 2026-10-12

## Scope

This step adds retention features without introducing a backend or runtime AI.

Implemented:
- daily observance reminders;
- configurable daily reminder time;
- Sunday weekly digest;
- reminders for selected favorites;
- reminders for followed categories;
- deterministic offline daily quiz;
- notification payload routing to an observance detail;
- Android Home Screen Widget with a rolling 14-day local schedule;
- locally rendered PNG share cards;
- canonical Android/iOS application identity enforcement.

## Provider baseline checked on 2026-10-12

- flutter_local_notifications: 22.3.1
- flutter_timezone: 5.1.1
- timezone: 0.11.1
- home_widget: 0.10.0
- share_plus: 13.3.1

The project deliberately uses AndroidScheduleMode.inexactAllowWhileIdle.
No SCHEDULE_EXACT_ALARM or USE_EXACT_ALARM permission is requested.

## Notification reliability policy

- Notification permission is requested only after a user explicitly enables a reminder.
- App initialization never triggers the permission dialog.
- Android scheduled notifications declare RECEIVE_BOOT_COMPLETED plus the plugin scheduling/reboot receivers.
- Daily reminders are pre-scheduled for a rolling 31-day horizon.
- Weekly digests are pre-scheduled for eight weeks.
- Favorite/category reminders use a 180-day occurrence horizon.
- Total generated pending requests are capped at 120.
- Every scheduled ID is deterministic from reminder type + date + observance id.
- Reconfiguration replaces the pending World Days schedule atomically.
- Failure to initialize or schedule notifications never blocks catalog use.

## Market interaction

Retention respects the selected market:
- global records are always eligible;
- national records are eligible only for the selected market;
- changing market rebuilds reminders and refreshes the Home Screen Widget;
- locale remains independent from market.

## Home Screen Widget

Android source is generated by tool/configure_platforms.py.

The Flutter layer stores a compact JSON schedule for the next 14 days through home_widget.
The native provider selects the entry matching the device date when refreshed by the launcher.
If no current entry is present, it falls back to opening World Days to refresh.

The widget is optional and must not block startup if unavailable.

## Share cards

Share cards:
- are rendered locally with RepaintBoundary;
- contain World Days branding, canonical title and authority;
- are encoded to PNG in memory;
- are shared through share_plus;
- do not use third-party artwork or copied editorial imagery.

## Native identity

Canonical package / bundle identifier:
com.riccardopinato.worlddays

tool/configure_platforms.py rewrites generated Flutter scaffold identity on every CI bootstrap and validates:
- Android namespace;
- Android applicationId;
- MainActivity package;
- iOS PRODUCT_BUNDLE_IDENTIFIER.

This fixes the default flutter create result that would otherwise derive identity from the Dart project name world_days.

## Remaining runtime certification

Source-level and CI gates can validate compilation and tests.
Before Store Ready certification, physical-device checks remain required for:
- Android 13+ notification permission UX;
- notification delivery across reboot / idle;
- notification tap deep-link;
- Home Screen Widget add/update/click;
- share sheet behavior on Android and iOS;
- iOS notification permission and delivery.
